# jkbase — L4 UDP scale-to-zero ingress design (protocol-agnostic)

> Status: design (L4-P0 — first external **non-HTTP** reach plane). The **entire control plane is BUILT + unit-tested** on branch `feat/l4-udp-ingress` (config type + preflight, `PortAllocation` store + CRUD + reuse quarantine, sticky bind-probed allocator, `_l4_ports.json` sidecar + host-authored `_l4.json` reach facts, deploy allocate/author/reconcile + teardown free/quarantine, `jkbase l4 ls` + admin `l4 pin`). The **runtime seam is REMAINING** (datagram pump + flow-id transit, agent UDP land-forward, generic wake-throttle + anti-reflection egress controls, firewall open, observability + on-box e2e). A short list of **control-plane deltas** the review surfaced (per-port tunable fields on `L4PortConfig`; the runtime socket-reconcile loop that materializes allocations) is called out inline and in §8.
> Companion to `docs/managed-rhypedb-tcp-ingress-design.md` (closest sibling: same edge/register/wake/relay spine) and `docs/zero-bounce-phase2-design.md` (the `:80`/`:443` socket hand-off this doc deliberately does **NOT** match).
> Scope: raw L4 ingress with scale-to-zero, **FULLY protocol-agnostic**. A tenant hosts *any* UDP service — game server, voice, custom binary protocol — behind an **always-on host edge socket** while the guest VM hibernates to zero and wakes (~125ms resume / seconds on a cold boot) on a datagram. **Stock, unmodified UDP clients point straight at `host:external_port` and speak only their own wire.** There is **no per-protocol code, no app-specific magic bytes, and no jkbase handshake injected into the app protocol.** A voice server on UDP `9987` (TeamSpeak) is used below only as an **illustrative example tenant** — never as a mechanism. TCP L4 is a follow-on whose *control* plane is shared but whose *data* plane is different and strictly easier (§3(e)).
> Threat model: **all tenants untrusted** (Firebase-scale public offering); this is a NEW external L4 seam whose trigger — a UDP datagram — is **source-spoofable and carries no completed handshake**. Unlike the HTTP plane (whose wake fires only after the kernel completes a TCP 3-way handshake, so the source is verified) a bare datagram proves nothing about its origin, **and — the load-bearing fact of this whole design — a generic edge cannot force a stock client to prove otherwise** (§1.1). Every defense flows from: *the source is unverified and unverifiable, so we bound the cost of a spoofed packet instead of trying to authenticate it.* The bounds are **provisioned and plane-isolated but not zero** — this doc states the residuals honestly and does not overclaim (§1.2, §3(c), §9).
> Produced via recon → design-synthesis → adversarial-probe (multi-reviewer), then **re-scoped generic** (return-routability removed — see §1 and §9/D3), then hardened against a second multi-reviewer pass (cost-DoS cross-tenant fair-share, C0 ratio, generic liveness, egress-map lifecycle, flow-id epoching). `[R#]`/`[P0-L4-#]` findings folded in.
> Decisions — PROPOSED (awaiting Joe's sign-off; see §9): (D1) UDP first, TCP different-data-path follow-on. (D2) guest binds **loopback + agent land-forward proxy**, NOT eth0-bind + firewall. (D3) **wake-on-first-packet, protocol-agnostic — bounded by rate/budget/egress caps, NOT by return-routability** (which is provably unavailable for stock UDP clients; §1.1). (D4) load-bearing axes: **cost-DoS** (per-base-project wake-rate + **per-tenant-fair-share** global concurrent-wake budget + **global distinct-warm-project ceiling** + host-RAM reservation) and **reflection** (per-source + per-project + per-/24 + **global** egress caps + ratio-based amp-clamp + generic keep-warm). (D5) admin-**pinned** external port for a well-known service (e.g. `9987`), random-alloc default + SRV fallback for others. (D6) new datagram pump — `relay_bidirectional` is NOT reused. (D7) new `UDP_RELAY_IDLE_TIMEOUT` on an **un-throttled per-datagram clock**; reuse `idle_detection_loop` *without back-dating the shared clock*. (D8) **NOT gapless across host-process restart** — clients reconnect.

## Hard constraints (honored throughout)

- (a) The guest L4 service binds **guest loopback only** (e.g. a voice server on `127.0.0.1:9987/udp`); the `jkbase-agent` is the sole in-VM mediator, exactly as rhypedb binds `127.0.0.1:4200/4201` (`crates/jkbase-agent/src/container_supervisor.rs:129-131`) and is reached only through the secret-gated splice (`crates/jkbase-agent/src/main.rs:519`). The service **never** binds eth0.
- (b) All tenants untrusted; this is a new external L4 UDP seam whose trigger is **source-spoofable and permanently unverifiable** (§1.1). We do not gate on source identity — we bound the damage a spoofed packet can do.
- (c) Scale-to-zero holds. The host edge `UdpSocket` per allocated port is always up; the VM still hibernates to zero and resumes on the first admitted datagram, then hibernates again when no traffic flows in **either** direction (§3(d)).
- (d) **Additive only, and plane-isolated — at the *resource* level, not just the admission level.** A `#[serde(default)]` config table + new store tables; zero migration; zero change to the DB (`db_ingress.rs`) or HTTP (`lib.rs`) plane semantics. The UDP plane gets its **own** wake budget, its **own** global warm-VM ceiling, and its **own** egress caps; it must not (i) couple to the other planes' budgets, (ii) back-date the shared hibernate clock (§3(d)), or (iii) squeeze the host RAM the stronger planes need to boot/stay resident — so it carries a **host-memory reservation** the other planes cannot be starved below (§3(c) axis 1).

## 1. Summary — what & why (the two central facts)

**Fact one (wire shape):** UDP is connectionless, so there is no socket to pin liveness on, no byte-stream we can hand to `relay_bidirectional`, and — critically — **no completed handshake that proves who sent the trigger.** Everything below is a consequence of manufacturing a *session* out of a stream of datagrams that are individually forgeable, **without** being able to manufacture a *verified source*.

**Fact two (why this is not "HTTP parity"):** the HTTP wake plane looks like it also "wakes on an unauthenticated `Host` match" (`lib.rs`), but its trigger rides *inside* an already-established TCP connection — the client had to receive the server's SYN-ACK and echo the correct ISN, which is only possible from (or on-path to) the claimed source IP. **So on the HTTP plane the source address is verified for free by the kernel; on a bare UDP datagram it is not, and for a stock client it cannot be (§1.1).** A design that wakes a VM (or emits a reply) on an unverified datagram hands an off-path spoofer a boot-per-packet resource amplifier and a traffic reflector against any victim IP it names. We do **not** claim source-parity with HTTP, and we do **not** try to recover it with a challenge. We accept the unverified source as permanent and instead **bound the two things a spoofed packet can cost us** — a boot, and a reply steered at a victim — to provisioned, plane-isolated, per-tenant-fair-share limits (§1.2). That is the whole job, and its output is bounded, not zero.

We already ship a reach plane that wakes a hibernated VM and splices a caller through the agent into a guest service: the managed-DB `:443` edge (`crates/jkbase-proxy/src/db_ingress.rs:100`) and its source-IP-authed host twin (`crates/jkbase-server/src/db_gateway.rs`). That plane's control half — edge caps, `register-before-wake`, `WakeCallback`, the relay registry that keeps the idle loop informed, RAII drain — is **transport-agnostic and mostly reused**; the two places it does **not** port cleanly (its preauth semaphore carries a per-source dimension we cannot keep, `db_ingress.rs:112`; its warm-VM registry is per-tenant with no global distinct-warm cap, `db_relay.rs:29-40`) are called out and fixed in §3(c). Only the *data path* is new: the DB splice rides TLS-over-TCP on the edge and HTTP/1.1-Upgrade over TCP on the agent leg. `relay_bidirectional` (`crates/jkbase-wsproxy/src/lib.rs:185`) is a pure byte-stream pump — `split` + `read` + `write_all` — with **no message framing and no per-packet `SocketAddr`**, so it coalesces/splits datagrams and loses the reply-demux key. It is fundamentally TCP-shaped and cannot be reused for UDP.

So v1 builds four things and reuses the rest: (a) a datagram relay with a **framed, flow-id-multiplexed** host↔guest transit leg (one host guest-facing socket per port, not per flow), (b) port-per-project L4 routing (no `Host`/SNI on UDP — routing is purely `external_port → project`), (c) a **generic wake-authorization + anti-reflection model** that never inspects the app wire and never asks the client to prove anything (§3(c)), (d) un-throttled-timer, keepalive-agnostic idle detection (§3(d)). The `api.`/`storage.`/`console.` reserved-host short-circuits are HTTP-`Host`-based and **irrelevant here**.

### 1.1 Why generic return-routability is impossible (not merely hard)

The obvious defense — before spending a boot, make the source prove it can *receive* at the address it claims (the UDP analog of the TCP handshake) — is **provably unavailable for stock UDP clients.** This is a structural impossibility, not an implementation gap, and it is the premise the entire model rests on.

**The capability asymmetry.** An off-path blind spoofer has **full send** capability (arbitrary forged source IP, high rate) and **zero receive** capability (it cannot see anything sent to the victim). Return-routability = *"prove you received a fresh value I sent to the address you claim,"* and proving reception **necessarily** requires the receiver to transmit back something derived from the received value. So:

- **Any scheme that only inspects what the source *sends*** — packet count, spacing, timing, holding the first packet, hashing the claimed IP into a token the client never sees — tests a capability the spoofer possesses *in full*, and therefore cannot distinguish spoofer from real client. (N-packets, delayed-reply, and HMAC-of-source are all trivially passed by a blind spoofer.)
- **Any scheme that *does* require proof of reception** requires the source to echo a fresh value — which for a stock client means **the application must echo it**, i.e. per-protocol code / a client shim / app-specific magic bytes. All explicitly out of scope.

There is no third category. **TCP** gets generic return-routability for free only because the echo (SEQ+1) lives in a *universal transport stack* every client implements identically — the app never participates. **UDP's transport layer echoes nothing on its own**; the only actor that can echo is the application. QUIC Retry and DTLS HelloRetryRequest *are* genuine return-routability — but **protocol-specific**: the client's QUIC/DTLS stack does the echo, and to emit a QUIC Retry the edge must first parse QUIC → per-protocol code → out of scope. Their existence *confirms* the theorem: every real UDP ecosystem pushed routability *up* into the security/application protocol precisely because bare UDP cannot provide it.

An edge-emitted challenge the client must echo is doubly disqualified: it (i) breaks 100% of stock clients (they speak only their own wire and either drop our bytes or feed them into their parser and reset), and (ii) is **itself a reflection primitive** aimed at the forged source — the exact amplifier we are trying to remove.

**Conclusion:** source *identity* cannot be validated at the generic UDP edge at all. So we stop trying. We make a spoofed packet worth almost nothing (§1.2) instead of trying to tell it apart from a real one — and we are explicit that "almost nothing" is a bound, not zero.

### 1.2 The two abuse axes and the honest bounds

Because the source is unverified and unverifiable, a single spoofed/anonymous datagram to an allocated `external_port` will (a) **cost** a boot and (b) **cause the guest app's first reply to be sent to whatever address the datagram named.** We cannot stop either at the level of one packet. We bound both — and we bound them *per-tenant* and *globally* so one attacker cannot convert them into cross-tenant denial or third-party amplification:

| Axis | What the attacker gets | Bound | Residual (honest) |
|---|---|---|---|
| **1 — cost-DoS** | a VM boot per trigger + a warm VM held up by traffic | per-base-project wake-rate cap + **UDP-plane-private** global concurrent-wake budget **with a per-tenant fair-share** + single-flight gating the permit (**exactly one permit per in-flight boot**) + boot-timeout force-release + `WakingGuard` + warm-VM quota + **global distinct-warm-project ceiling** + host-RAM reservation | one warm VM per *targeted L4-enabled project*, capped boot churn; a flood can starve at most **its own** fair-share of the global budget, not other tenants' cold wakes; the UDP plane cannot drive HTTP/DB into RAM pressure |
| **2 — reflection/amplification** | the app's reply steered at a spoofed victim IP | **ratio** amp-clamp (egress credit accrues `k`×ingress **bytes**, default `k`=1) + one-shot per-new-source floor `C0`≈1 MTU (rate-limited per-port **and** globally) + per-source(**IP**) burst/rate cap + per-project egress cap + per-/24 destination backstop + **global platform egress budget**; keep-warm generic (§3(d)), reflection-suspected flows killed by the abuse kill-switch | **sustained ~1×** (≤`k`, up to a per-port-configured slack ≤3); a **one-shot** ≤`C0` per fresh spoofed victim (a *spray*, rate-limited, never a *concentration*); **source-IP laundering** (inherent to any stateless forwarder). No sustained amplification leverage — orders below DNS/NTP/memcached |

The design principle that *replaces* return-routability: **per-source keying is worthless on the wake axis (the source is spoofable) but decisive on the egress axis (the "source" is the address we are about to reply *to* — capping it directly caps what a victim receives).** So per-source limiting moves *out* of the wake gate and *into* the egress path — keyed on the destination **IP** (§3(c) axis 2, closing the source-port-rotation multiplier).

**Removed relative to the earlier draft of this doc:** the magic pre-filter, the stateless return-routability cookie challenge and its per-protocol adapter, the "one-RTT-before-boot" and "echo-able-handshake-only" limitations, and the claim that anything gates the *wake* on source authenticity. **Kept:** transit-leg per-datagram auth (P0-L4-11), loopback-only guest (P0-L4-1), flow-table bounding (P0-L4-5), port allocation/stickiness/quarantine (§3(b)), datagram-boundary preservation (P0-L4-7), flow-id epoching (P0-L4-13), fail-closed everywhere (P0-L4-9).

## 3. Design detail

### 3(a) UDP datagram relay — new listener + flow-id-multiplexed transit

**BUILD NEW (REMAINING).** A `L4Ingress` struct (the UDP analogue of `DbIngress`, `db_ingress.rs:100`) owns, per allocated port:
- one always-on host **edge `UdpSocket`** (client-facing: `recv_from`/`send_to`),
- one host **guest-facing `UdpSocket`** toward `vm_ip:agent_udp_port` (§3(b) — **one per port, NOT one per flow**),
- a **flow table `HashMap<SrcAddr, Flow>`** where `Flow` is pure bookkeeping — a `flow_id: u32` **with an epoch/generation** (P0-L4-13), a `RelayGuard` (attached only on promotion, see below), an **un-throttled** last-seen `Instant`, an egress-credit counter (§3(c) axis 2), and a `provisional | established` state (§3(c)). It holds **no socket and no task per entry** (this is what bounds host-side fd/ephemeral cost — see P0-L4-5).

The pump is two loops, not a task-per-flow, and **never awaits a boot inline** (a single edge socket has one recv loop; awaiting a multi-second cold boot in it would head-of-line-block every warm flow on the port — mechanics H1):
- **Reach loop** (`recv_from` on the edge socket): look up/admit the flow. On a miss run **only the synchronous non-blocking gates** (§3(c) axis 1 steps 1–5), then **spawn** the boot + first-packet buffering and immediately continue `recv`-ing. On a hit or a post-readiness admitted flow → frame `{auth-hdr(HMAC(splice_secret, flow_id ‖ epoch ‖ nonce ‖ payload)) ‖ datagram}` (§3(a-auth)) → `send` on the single guest-facing socket.
- **Return loop** (`recv` on the single guest-facing socket): verify+strip the agent's auth-header, read `(flow_id, epoch)`, look up the client `SrcAddr` (rejecting a stale epoch — P0-L4-13), run the egress controls (§3(c) axis 2), `send_to(src)` on the edge socket. **`(flow_id, epoch)` is the reply-demux key** `relay_bidirectional` lacks (P0-L4-7).

`flow_id` is a **per-port monotonic counter with a generation/epoch**, **never a hash of `src`** (a hash aliases two sources onto one demux key → cross-client reply mis-delivery; mechanics H3). A reused numeric `flow_id` carries a fresh epoch, and **reuse is quarantined until in-flight replies for the prior epoch drain** (mirrors the port-quarantine of §3(b)), so a late reply for the old owner can never be delivered to the new one. Host flow eviction sends a **synchronous teardown signal** over the transit leg so the agent invalidates its `(flow_id,epoch)→socket` entry in lockstep, not lazily (closes the host/agent independent-eviction cross-wire, mechanics M2/M5).

Because return demux is by `(flow_id,epoch)` in a framed header, the host needs **no per-flow socket** and **no per-flow task** — the two shared loops plus a periodic sweep over the flow table for idle eviction (sweep tick kept well under the 5s provisional timeout so provisional flows don't overstay — mechanics L3; a `flow_table` HIT takes a per-entry state check so a relay can't race the sweep evicting the same entry — mechanics L1). This is the direct fix for host ephemeral-port / task exhaustion under a flow flood.

**Agent side (BUILD NEW, REMAINING):** a UDP land-forward listener modeled on the agent's loopback DB reach (`crates/jkbase-agent/src/main.rs:519`). It receives framed transit datagrams on `agent_udp_port`, **const-time verifies + strips** the host auth-header (§3(a-auth)), and forwards the payload to `127.0.0.1:guest_port`. Reply demux **does** require per-flow guest-side sockets (the app replies to whatever source the agent presented), so the agent keeps a `(flow_id,epoch) → connected loopback UdpSocket` map — but that map has its **own explicit bound** `≤` the host per-project cap, sized to the microVM's fd/RAM headroom, fail-closed on overflow, epoch-synced to host eviction, and idle-evicted. State the FD budget on both sides in the impl. "The agent just needs a firewall rule" is the **wrong** model: a direct eth0 bind would bypass the entire wake/quota/idle machinery and expose an unauthenticated UDP service to the hostile L2 segment [P0-L4-1].

**Client-identity continuity across hibernate (mechanics H4).** The agent presents each flow to the guest as a distinct *loopback* socket (`127.0.0.1:ephemeral`); a stateful app that keys sessions on that tuple would see a **new peer** every time a silent-but-live flow is evicted and re-woken — a session reset, not a latency blip. So the agent **persists a `client-identity (external SrcAddr) → stable loopback source port` binding for longer than the flow** (its own TTL, evicted on the same abuse/idle horizon as the port quarantine): a re-wake of the same client reuses the same loopback port ⇒ same app-visible peer. This is best-effort continuity, not a guarantee across host-process restart (D8); the honest limitation — *stateful L4 apps should key sessions on their own protocol identifiers, and the most aggressive scale-to-zero is mildly incompatible with tuple-keyed session state* — is documented in §5 and §9.

**Why not `relay_bidirectional`** (`wsproxy/src/lib.rs:185`, hooked variant `:196`): its `AsyncRead`/`AsyncWrite` byte model has no datagram boundary and no `SocketAddr`/`flow_id` per packet [P0-L4-7]. We keep its `RelayHooks` (`wsproxy/src/lib.rs:35`) *semantics* — `select!` on the `CancellationToken` — but implement the copy loops over `UdpSocket` with framed transit.

**Bookkeeping reuse — split into reservation and promotion (mechanics H2).** `DbRelayRegistry::try_register` (`crates/jkbase-proxy/src/db_relay.rs:110`) / `RelayGuard` (`db_relay.rs:297`) / the `conn_count` gauge (`db_relay.rs:220`) are one coupled unit and **cannot be reused as-is** — calling `try_register` at admission would let provisional spoof-flows consume the tenant's warm-VM quota (self-`OverQuota`) and mirror into `conn_count>0` (pinning the VM warm). So admission is a two-phase split: a **reservation** (§3(c) axis 1 step 2) bounds the flow table per-project + globally and does **not** touch `conn_count`; **promotion to established** (§3(c) axis 2 / §3(d)) is what calls `try_register` and attaches the `RelayGuard`, bumping `conn_count` and pinning the VM warm. The **live-flow gauge mirrors `conn_count`** and counts **only established flows** (P0-L4-12).

#### 3(a-auth) Host↔guest transit authentication — the connectionless leg (already generic)

The DB agent leg authenticates a **secret in a per-connection TCP/HTTP-Upgrade preamble** validated once (`agent/src/main.rs:519`). UDP has no connection, so that check **does not port** — we do not claim it does. On a shared L2 bridge, a co-tenant can address (or spoof toward) the agent's transit listener, so **every** host→guest datagram carries a fixed-size authenticated header, and the listener is additionally L2-source-guarded. Two layers, both **protocol-agnostic** and unchanged by the generic re-scope:

1. **Per-datagram authenticated header (defense-in-depth #1).** The host prepends `{ flow_id, epoch, monotonic nonce, HMAC(per-VM splice secret, flow_id ‖ epoch ‖ nonce ‖ payload) }`. The **`splice secret` is the existing per-VM splice secret** the DB/agent leg already uses (`agent/src/main.rs:519`) — reused, so **no new `_l4.json`/agent field and no delta to the DONE reserved-channel authoring** (completeness H4). The agent const-time-verifies the HMAC and **rejects replays** via a per-flow high-water nonce window **scoped to `(flow_id,epoch)`** (so a `flow_id` reuse starts a fresh, unambiguous window — mechanics M5), then strips the header before `send_to 127.0.0.1:guest_port`. The return direction is symmetric (agent proves it is the real agent). The "secret in the first datagram only" and "silently trust the host source IP" alternatives are both rejected (either leaves subsequent datagrams unauthenticated or is L2-spoofable). **P0-L4-7 scope:** the transit wire carries exactly one framed record per client datagram (no coalescing); the client↔edge and agent↔app legs are raw datagrams.
2. **L2 source-guard (defense-in-depth #2).** The agent transit listener is pinned so only the **host TAP source** is admitted, using the same ebtables/anti-spoof source-guard that fences build egress (dockerfile-builder L2 source-guard work) — a co-tenant cannot forge the host's L2/L3 source onto the bridge. Preferred posture: keep the seam on the **host-side bridge-gateway path** the DB gateway already uses (`db_gateway.rs` binds `172.16.0.1`), not a fresh guest eth0 surface.

This leg is identical for any UDP payload — it never inspects the app wire.

### 3(b) Port-per-project L4 routing — DONE (control plane) + one runtime delta

### 3(c) Generic wake-authorization + anti-reflection (no return-routability) — REMAINING

The trigger is source-spoofable and unverifiable (§1.1), so we do **not** try to authenticate it. We wake on the first packet and bound the two things a spoofed packet can cost us. Two axes; the machinery of each is protocol-agnostic and never inspects the app wire.

#### Axis 1 — bounding platform cost-DoS (wake-on-first-packet)

Admission on the edge `recv_from` loop, in the sibling's register-before-wake slot (`db_ingress.rs:214`) — but restructured so that (i) the boot is **spawned, not awaited inline** (no head-of-line block, mechanics H1), (ii) the **single-flight gates the global permit** (exactly one permit per in-flight boot, mechanics B1), and (iii) the global gates carry a **per-tenant fair-share** so a spoof flood cannot monopolize them (threat B1). No challenge, no per-source pre-wake state:

```
recv_from(src)                                   # src UNVERIFIED, never trusted
  ├─ flow_table.get(src) HIT (warm) ─▶ relay (NO wake)
  └─ MISS:
       1 per-base-project WakeRateLimiter.try()  ── over ─▶ DROP (RateLimited)
       2 flow RESERVATION: per-project + GLOBAL flow-table (per-tenant
           fair-share) ── full ─▶ DROP (flow_full_project|flow_full_global)
           # reservation only — does NOT call try_register / touch conn_count
       3 single-flight: wake for base_project already in-flight?
           YES ─▶ coalesce (buffer this datagram onto the pending boot),
                  take NO second permit
           NO  ─▶ 4 udp_wake_budget.try_acquire_owned() within this tenant's
                     fair-share  ── none ─▶ DROP (budget_full)
                  5 global distinct-warm-project ceiling ── full ─▶ DROP (warm_full_global)
                  6 SPAWN boot task { WakingGuard single-flight; boot-timeout
                     force-releases the permit + slot }; RETURN to recv
       (on readiness) replay buffered datagram(s); admit PROVISIONAL flow F
```

**Why the source being spoofable does not help the attacker here:** every gate at steps 1–5 is keyed on **`base_project_id`** or is **global with a per-tenant fair-share** — *none* is keyed on source IP. So rotating/spoofing source addresses (which would defeat any per-source pre-wake cap) buys the attacker nothing. The attack collapses to "how fast can I wake / how warm can I hold projects I am allowed to target," and the fair-share + global ceilings bound its cross-tenant blast to its own share.

- **Per-base-project wake-rate cap** — a `WakeRateLimiter` (sibling of `PerIpLimiter`, `db_ingress.rs:35`; RAII decrement + prune-at-zero like `IpPermit` Drop `db_ingress.rs:70`), token bucket keyed on `vm_identity::base_project_id` (`crates/jkbase-server/src/vm_identity.rs:66`) so app + `.db` sibling VMs share **one** budget. **Default: 5 tokens, refill 1/2s (≈ burst 5, sustained 0.5 wake/s).** Keyed on base-project **not `(project,port)`** so extra ports can't multiply the cap. Slots *before* the spawn.
- **Global UDP-plane concurrent-wake budget, per-tenant fair-share** — `udp_wake_budget: Arc<Semaphore>` (default **16 permits**), acquired **non-blocking** `try_acquire_owned` (mirroring the DB spine's `global` semaphore, `db_ingress.rs:109`/`:138`), **but with the per-source dimension the DB spine used replaced by a per-tenant reservation** (`db_ingress.rs:112` kept a per-source cap "so one host can't hold every global slot"; we cannot key on the spoofable source, so we cap **each base-project to a fair-share** — default **≤4** of the 16 — so a flood starves only its own share, not other tenants' cold wakes). The permit is held across the boot **but bounded by a boot-timeout force-release** (mechanics M4: a hung boot cannot leak a permit) and **guarded by the single-flight** so a per-project burst of 5 packets produces **one** permit, not 5 (mechanics B1). **NOT shared with the HTTP or DB planes** — the spoofable UDP plane must never starve the stronger planes' cold boots. A failed acquire ⇒ `DROP`, never a parked task.
- **Global distinct-warm-project ceiling + host-RAM reservation (NEW — threat H1).** `registry.try_register` bounds warm VMs **per-tenant** only (`db_relay.rs:29-40`; `db_ingress.rs:85-88` confirms there is no seam-level global cap), so nothing today bounds the *number of distinct projects* warm across tenants — a spoofer touching every L4 project on a host could mass-wake N VMs and squeeze the RAM HTTP/DB VMs need to boot. So the UDP plane carries **its own global ceiling** on distinct concurrently-warm UDP projects (count and/or aggregate RAM) **and a host-memory reservation the UDP plane cannot dip into**, so HTTP/DB boots are protected at the *resource* level, not just at wake-admission. Step 5 gate; over-ceiling ⇒ `DROP (warm_full_global)`.
- **Per-tenant warm-VM quota (reused, on PROMOTION not admission — mechanics H2)** — `registry.try_register(base_project)` (`db_relay.rs:110`) is called when a flow **promotes to established**, not at admission; a provisional flow holds only a flow-table *reservation* (step 2) and does **not** consume the warm-VM quota or `conn_count`. `Rejected` ⇒ the flow stays provisional / is dropped.
- **`WAKE_BACKOFF` + `wake_project` quota + `WakingGuard` (reused, inside the spawned boot)** — `WAKE_BACKOFF` (`main.rs:3971`, enforced `:4086`, `bail!` `:4089`) throttles *failing* wakes; the `wake_project` quota gate (`main.rs:3977`, `bandwidth_blocked → OverQuota` `:3991`/`:3993`) still applies. `WakingGuard` single-flight (struct `main.rs:3930`, Drop `:3950`, construction `:4152`) guarantees a concurrent burst for one cold project produces **exactly one** boot — and, per the restructure above, **exactly one global permit**.
- **Per-project allocated-port hard cap (enforced in v1)** — default 8 ports/project, enforced in `allocate_port` (`store.rs:926`), fail-closed at deploy. Bounds always-on socket count *and*, because the wake cap is base-project-keyed, prevents port-multiplication of the wake axis.

**Enum:** add `WakeError::RateLimited(String)` at `crates/jkbase-proxy/src/lib.rs:31` (beside `OverQuota` `:34` / `Unavailable` `:36` / `Gone` `:40`); the UDP responder drops silently; promote the `WAKE_BACKOFF` `bail!` (`main.rs:4089`, currently blanket-mapped through `Unavailable` at `main.rs:4019`) to it so rate-cap vs failure-throttle read distinctly in metrics.

**Total worst-case platform cost of an unbounded spoof flood:** `≤ 16` instantaneous boots (global budget, and `≤4` attributable to any one tenant) **+** `≤` the global distinct-warm ceiling of warm VMs (each self-hibernating when the flood stops), **with a host-RAM floor reserved for HTTP/DB**. Finite, provisioned, and — this is the corrected claim — **bounded cross-tenant**: a single flood can deny at most its own fair-share, cannot exceed the global budget, cannot exceed the global warm ceiling, and cannot drive the other planes into RAM pressure.

#### Axis 2 — bounding third-party reflection/amplification

The attacker sets `src = victim`. We boot (bounded by Axis 1), forward to the guest, the guest app replies, and the edge `send_to(victim)`. We cannot verify `src`, so we cannot *stop* the first reply. We make the reflection **worthless** by capping reflected volume to a *ratio* of what the attacker sent and hard-capping the absolute rate at every aggregation level. **Crucially, the edge never emits an unsolicited packet toward an unvalidated source** — no challenge, no error, nothing (that is what would make the edge itself a reflector, §1.1). Only the guest app ever replies, and its replies are metered.

Egress controls, evaluated on the return loop **before** `send_to(src)`. The numbers **nest monotonically in one unit** (mechanics M2): `C0 (one-shot) < per-source < per-/24 < per-project < global`.

1. **Per-flow amplification clamp (THE core bound) — a *ratio* egress-credit bucket.** Receiving `b` bytes from source `S` adds `k·b` credits to `S`'s flow bucket; sending `b` bytes to `S` costs `b` credits; egress is permitted only while credit ≥ 0. Excess is **dropped, not queued**. **Default `k = 1`** (byte-for-byte). `k` is a **per-port tunable** (`amp_k ∈ 1..=3`, default 1) with the ceiling 3 = QUIC's anti-amplification number, because a *strict* 1× breaks legitimate protocols whose first reply exceeds the first request. **Credit is a ratio of bytes *actually received*, not an absolute allowance** (fixing the earlier "absolute `C0`" flaw that made the first-packet ratio `C0/request_size` ≈ 64–200× — threat H2).
   - **One-shot floor `C0` for the first reply datagram.** UDP datagrams are indivisible — you cannot send 4 KB of a 6 KB reply, so a first reply larger than the tiny handshake request would be **silently dropped whole** and never "catch up" (permanent silent failure of the first exchange — mechanics H6). So a **brand-new source (keyed on IP, item 2)** gets a **one-time `C0` grant** (default **≈1 MTU / 1.5 KB**, an internal constant, not tenant-tunable) that lets the flow go up to `C0` negative **once**, admitting a single first-reply-bigger-than-request datagram (DTLS/QUIC cert chain, game connect→snapshot, TFTP body). After that one datagram it is **strictly `k·ingress`**. `C0` grants are rate-limited **per-port** (default ≤50/s, burst 200) **and against a global `C0`-grant budget** (item 5). **Honest bound:** the worst-case *first-packet* amplification is `C0 / request_size` for **exactly one datagram per fresh source**, rate-limited both per-port and globally — a bounded *spray*, never a sustained factor, and dominated by the attacker hitting the victim directly. When a datagram is dropped for lack of credit, the flow is **marked** and an `egress_amp_clamp` counter increments (never a silent whole-datagram drop of a handshake reply, mechanics H6).
2. **Per-source (reply-destination) token bucket + burst cap — keyed on destination IP (`/32`, /64 for v6).** **Default: 1 MB/s sustained, burst 64 KiB.** Keyed on **IP only, not `ip:port`** (else a spoofer rotating the victim's source *port* mints a fresh bucket + fresh `C0` per port — a 65 k× multiplier; threat M3 / completeness H3 / mechanics M1). The per-source and per-`C0` state **persists across flow churn** in a map with an **explicit cardinality bound + LRU/idle TTL eviction, fail-closed (drop egress) on overflow** — same rigor as the flow table (P0-L4-5), because the accepted `C0`-spray residual otherwise grows this map without bound.
3. **Per-project egress aggregate cap.** A token bucket over all of a project's flows, riding the existing metering quota. **Default: 16 MB/s / project** (admin-overridable per project). Sized against a realistic large
meeting: a 50-way conferencing SFU forwarding top-3 audio with thumbnails on a simulcast low layer
offers ~11 MB/s, and a 20-way ~15 MB/s. (A widely-quoted 43.5 MB/s figure for the same meeting
assumes full audio fan-out to every participant and 600 kbps per thumbnail — neither is a workload
any SFU ships.) Bounds a compromised/hostile tenant app from being fanned out across many spoofed victims at once.
4. **Per-remote-/24 (v6: /64) destination backstop.** A platform-wide attacker spreading a *concentration* across many projects at one victim network is capped by a global per-destination ceiling. **Default: ~8 MB/s per /24.**
5. **Global platform egress budget + global `C0`-grant budget (NEW — threat M1 / completeness M1).** The per-/24 backstop stops *concentration* but not a *distributed* `C0` spray at many distinct victim networks. So two genuinely-global controls ship with the feature: a **global platform egress ceiling** (default ~64 MB/s across all projects) and a **global `C0`-grant rate** — so the aggregate one-shot spray is bounded platform-wide, not merely per-port.

**Keep-warm / billing (P0-L4-12, reconciled with generic liveness §3(d) and threat H3 / completeness H5).** A flow is admitted **provisional**: it does **not** increment `conn_count`, does **not** pin the VM warm, does **not** accrue billable warm-hours, carries a short **provisional idle timeout (default 5s, fixed)**, and the one-shot-only `C0`. It is promoted to **established** only after **sustained admitted traffic** — a concrete threshold: **≥ `MIN_ESTABLISH_BYTES` / `MIN_ESTABLISH_PKTS` over ≥ `MIN_ESTABLISH_MS`** (internal constants) — **in either direction** (the generic definition; see §3(d)). Only established flows call `try_register`, bump `conn_count`, pin warm, and are billing-eligible.

**Honest residual (P0-L4-12 corrected — does NOT claim to prevent economic-DoS).** "Sustained bidirectional liveness" was overclaimed: `established` ≠ *verified peer*, and it never can be (§1.1). A **funded attacker** that continuously spends ingress with `src = victim` supplies the "sustained traffic" itself; the guest keeps replying within credit; the flow promotes → `conn_count++` → **pins that one targeted tenant's single VM warm**. So a funded sustained-ingress attacker **can** hold one targeted VM warm and (were billing enabled) run up its owner's bill. We do **not** claim to prevent this; we bound and mitigate it: (i) it is one VM per *targeted* project, bounded by the wake-rate + global warm ceiling; (ii) **UDP warm-hours are UNBILLED in v1** (§6), and the design does not rely on establishment-gating to *solve* economic-DoS; (iii) a flow with a **high egress:ingress ratio or a high destination-entropy signature is force-hibernated by the automatic abuse kill-switch** (§8), not left riding as "established." *"Reflection-suspected" is defined operationally* as: sustained egress:ingress ratio above the port's `k` for longer than a window, **or** a per-project destination-entropy spike (many distinct low-volume `src`s) — those warm-hours are the ones §6 marks unbilled.

**Where this lands versus classic reflectors:**

| Reflector | Amplification | Note |
|---|---|---|
| DNS ANY | ~54× | tiny query → large RRset, stateless, no rate limit |
| NTP monlist | ~556× | one request → 100s of records |
| memcached | ~50 000× | KB request → MB stats, no auth |
| **jkbase generic L4 relay (this design)** | **sustained ~1× (≤3× if a port opts `k` up); one-shot ≤`C0` (≈1 MTU) per fresh source, rate-limited per-port + globally** | ratio credit-clamp caps *sustained* egress at `k`× ingress regardless of app amplification; the only fire-and-forget primitive is the rate-limited one-shot `C0`, which is a spray not a concentration |

A `k`-bounded reflector that costs the attacker `1/k` of the output in real bandwidth and cannot run unattended is not worth building a booter around next to a 50 000× fire-and-forget box. The **irreducible residuals** — all inherent to protocol-agnosticism, all *contained not removed*: (i) the ~1×–3× sustained factor (deliberate, metered, costs the tenant money via §6); (ii) the small `C0` one-shot **spray** (each fresh spoofed victim can draw up to `C0` for one datagram — bounded by `C0` size + the per-port and global grant rates + `k` on everything after; cannot be driven to zero without breaking reply-heavier-than-request handshakes); (iii) **source-IP laundering** (the victim's abuse desk sees jkbase's IP — inherent to *any* stateless UDP forwarder; mitigated by fast per-project detection + the automatic egress kill-switch + the operator runbook, §8). We do **not** assume BCP38/uRPF upstream; if present it narrows the vector but the design must not depend on it.

### 3(d) Generic idle detection (no keepalive assumption, no protocol-shape assumption)

**REUSE `idle_detection_loop`** (`main.rs:4568`) — it excludes any project whose `conn_count` gauge (`db_relay.rs:220`) is `>0` (`main.rs:4623`), so a byte-silent-but-live *established* flow stays warm for free. Four corrections, all protocol-agnostic:

- **Liveness is defined generically — sustained admitted traffic in EITHER direction, NOT two-way (completeness H1).** An entire legitimate class of UDP services is inbound-only (syslog, statsd/metrics ingest, telemetry sinks, one-way media receive). A "guest must reply to promote/keep-warm" rule would leave those flows forever provisional → hibernating every 5s and re-woken under the wake tax, and hibernating mid-stream while data still arrives. So **promotion and keep-warm gate on sustained inbound *or* outbound traffic**; the reflection defense lives entirely on the **egress** side (§3(c) axis 2), so keep-warm does **not** need bidirectionality to be safe. (An optional per-port `traffic_shape = "request_reply" | "inbound_only" | "streaming"` hint may tune thresholds, but the **default must not brick a one-way app**.)
- **Un-throttled per-datagram eviction clock.** The reused `on_activity` stamp is throttled to `ACTIVITY_STAMP_INTERVAL = 30s` (`wsproxy/src/lib.rs:30`). The per-flow eviction timer must **not** reuse that throttled stamp — it keeps its **own** last-seen `Instant`, stamped on **every** admitted datagram in **either** direction, else an actively-talking flow whose throttled stamp last landed at t=0 gets evicted mid-session.
- **Configurable per-port timeout; hibernate on N seconds of no traffic *either direction*.** `UDP_RELAY_IDLE_TIMEOUT` **default 60s**, per-port tunable, **floor 15s, ceiling 600s**. The model makes **no keepalive assumption** — a generic UDP app may be bursty or long-silent — so the default is deliberately generous and the failure mode is documented: *if an app's silence gaps exceed the configured timeout, the flow is evicted and re-woken on the next datagram; the tenant tunes the port's timeout to its app's traffic shape.* **Absence of traffic in both directions IS the only generic disconnect signal available.**
- **Do NOT back-date the shared hibernate clock (mechanics H5 — the plane-isolation fix).** The earlier draft "force-aged the project's `ActivityTracker`" on last-flow eviction to avoid a ~600s scale-to-zero lag. But `ActivityTracker` is the **shared** per-project hibernate clock the HTTP/DB planes also stamp; back-dating it can mark an HTTP-*active* project (whose `conn_count` is momentarily 0 between requests) as a hibernation candidate and snapshot it mid-serve — exactly the cross-plane coupling constraint (d) forbids. Instead, **L4 keeps its OWN per-project last-datagram `Instant`** and the hibernate decision uses `max(over all planes' last-activity) AND conn_count == 0`. When L4's flows drain, L4's own signal ages; if the HTTP/DB clocks are also aged (those planes genuinely idle), `max(...)` is old ⇒ prompt hibernate — **with no L4 write to another plane's timestamp** and no premature hibernation of a live HTTP/DB project.

Provisional flows (§3(c)) use the short **provisional idle timeout (5s)** and do **not** hold the room non-empty — a spoof flood that never establishes cannot pin the VM warm past 5s of silence. Effective hibernate latency for an established flow = `UDP_RELAY_IDLE_TIMEOUT + grace + poll-jitter (~≤60s)`.

### 3(e) What TCP L4 reuses vs. rebuilds (follow-on scoping)

The **control** plane is genuinely transport-agnostic and extends unchanged: the config table, `PortAllocation`/`agent_udp_port`/stickiness/quarantine, `allocate_port`, wake throttle + budget, teardown/reconcile, firewall open, admin pin-grant. The **data** plane inverts for TCP and is **strictly easier** — do **not** assume it is "just add `proto=tcp`":
- TCP **has** a handshake, so **return-routability is provided for free by the kernel completing SYN/SYN-ACK/ACK** — the entire Axis-1/Axis-2 spoof-mitigation apparatus of §3(c) is unnecessary; the source is verified before the app ever sees a byte.
- `relay_bidirectional` (`wsproxy/src/lib.rs:185`) becomes the **right** pump — a TCP byte-stream copier; the framed flow-id transit and per-flow demux are unnecessary.
- Idle detection can use **socket close / half-close** instead of an un-throttled timer.
So the TCP follow-on is a *different, simpler* data path bolted onto the *same* control plane. Out of v1 scope.

## 4. Threat model — invariants

All tenants untrusted; **the trigger is source-spoofable and permanently unverifiable for stock clients (§1.1)**, so no source is ever trusted and the defense is *bound-the-cost*, not *validate-the-source*. Bounds are provisioned and per-tenant-isolated but **not zero** — residuals are stated, not hidden. Most-critical first.

| ID | Invariant | Why / mechanism |
|---|---|---|
| **P0-L4-4** | **The plane accepts spoofable, unverified sources — generic return-routability is IMPOSSIBLE for stock UDP clients, not merely unimplemented (§1.1).** | Return-routability requires the source to prove *receive* capability; a blind spoofer has full *send* and zero *receive*, so any send-only scheme is passed trivially and any receive-proving scheme needs app cooperation (out of scope). ## 5. Lifecycle edge cases

- **Cold-boot UDP-readiness gate (`/proc/net/udp`, not a probe) — with a give-up path.** `wait_for_agent` (`main.rs:6595`) probes guest TCP `:80` — correct for **snapshot resume**, but on a **cold boot of a pure-UDP app** `:80` answering does **not** mean `127.0.0.1:guest_port/udp` is bound, and there is **no reliable active UDP liveness probe**. **Fix:** the agent polls `/proc/net/udp` for the loopback `guest_port` bind before replaying buffered datagram(s). Match **both** `0100007F:PORT` (a `127.0.0.1` bind) **and** `00000000:PORT` (a `0.0.0.0` bind — the common default; matching only loopback would leave a `0.0.0.0`-binding app permanently unreachable — mechanics M2). Add a **bounded readiness timeout**: on expiry, **drop the buffer and negative-cache the project as "L4 not ready" for a cooldown**, so a crashed/misconfigured-port tenant does not enter a **boot loop** (every packet re-waking → wait-forever → hibernate → repeat, burning the wake tax). Fully generic: any app that binds its declared `guest_port` satisfies it.
- **Bounded first-packet replay [R-replay].** Buffer the datagram(s) that arrive during cold boot; replay **after** the readiness signal. **Cap it hard** (a few packets / small byte ceiling); overflow ⇒ drop — the client retransmits. Replay only ever forwards *inbound* datagrams to the guest (never emits toward `src`), so it is not a reflection vector. Note: bounded replay + the client's own handshake retransmit can **duplicate-deliver** to the guest — tolerated by most UDP apps, but non-idempotent "join" handlers must expect it (mechanics L2).
- **Stateful session identity across hibernate (mechanics H4).** A silent-but-live flow that is evicted and re-woken gets a **new** agent loopback ephemeral port ⇒ an app keying on the loopback tuple sees a new peer (session reset). The agent's persistent `client-identity → stable loopback source port` binding (§3(a)) preserves continuity across a re-wake within its TTL; beyond that (or across host restart, D8) continuity is not guaranteed. **Documented limitation:** stateful L4 apps should key sessions on their own protocol identifiers; the most aggressive scale-to-zero is mildly incompatible with tuple-keyed session state.
- **First-connect-after-deploy blip.** With no snapshot yet, wake is a **full cold boot** (> the ~125ms resume), which can exceed a short-connect-window app's first attempt. One-time blip: the client retries, the now-warm/snapshotted VM answers. **Document; do not special-case.**
- **Host-restart flow-table loss = reconnect (NOT socket-activation).** The always-on edge socket is re-bound by a **plain in-process bind** — **NOT** socket-activated: systemd `.socket` units pre-declare a *static* port, and L4 external ports are dynamically allocated, so the `:80`/`:443` adoption path (PRs #59/#60) **does not apply**. The in-memory flow table + agent-side sockets are lost. Explicit **non-goal: NOT gapless across host-process restart** (D8). UDP clients resume sending; the next datagram re-wakes into a fresh flow (fresh epoch).
- **NAT source-port rebinding.** Flows key on `ip:port`; a client whose NAT rebinds its source port mid-session becomes a *new* flow (fresh admission). Expected and cheap.
- **Datagram size / MTU — hard provisioning requirement.** `recv_from` **silently truncates** past the supplied buffer, so relay buffers are sized to the max UDP payload (65507) or the negotiated app max. The transit leg adds the auth-header (`flow_id`+`epoch`+`nonce`+HMAC ≈ 44 B), so **"guest TAP MTU ≥ client-facing MTU + transit-header size" is a HARD requirement enforced at VM bring-up** (mechanics M3), not a doc note — else a full-MTU client datagram (1472 B → ~1516 B transit) exceeds a 1500 TAP MTU and every full-MTU packet draws `EMSGSIZE`/fragmentation (i.e. most game/voice/QUIC traffic). DF-set oversize behavior is defined: **drop that datagram only (with an `egress`/transit counter), never wedge the flow.**
- **IPv4/IPv6 — v6 keying is a BLOCKING prerequisite, not a convenience (threat M3 / completeness H3).** v1 ships **v4**. Dual-stack is a follow-on, but its aux-map keying **must be decided now**: per-source and `C0` grants key on **/64** (a /128 spoofer rotating within its /64 would mint fresh per-source state + `C0` per packet, nullifying the per-source cap), and the destination backstop keys on a v6 aggregate (/64 or /48). This is a hard v6 gate, flagged so the map key/eviction sizing isn't retrofitted.

## 6. Metering / quota / billing (generic)

Stated honestly as **what is wired in v1 vs deferred**:

- **Allocated L4 port count — hard-capped, enforced v1** (default 8/project; exceed ⇒ deploy fails closed, `store.rs:926`). Bounds public-port exhaustion, always-on-socket count, **and** the base-project-keyed wake axis.
- **Wake-rate + budget + warm-ceiling — metered signals v1.** The per-base-project cap, the fair-share budget, and the global distinct-warm ceiling each emit drop-reason counters (§8); excess ⇒ `RateLimited`/`budget_full`/`warm_full_global`.
- **Egress caps — enforced v1** (ratio amp-clamp + one-shot `C0` + per-source(IP) + per-project + per-/24 + global). Drop-reason counters on each; per-port egress:ingress ratio + distinct-destination entropy emitted so an amplifier/spray signature trips the automatic per-project egress kill-switch (§8).
- **Warm-VM-hours — instrumented, billing DEFERRED to v-next, and reflection-suspected hours UNBILLED by construction.** Only **established** (sustained-traffic) warm-hours are billing-eligible; a flow flagged **reflection-suspected** (sustained egress:ingress ratio above the port's `k`, or a per-project dest-entropy spike) is excluded. Per the corrected P0-L4-12, a funded attacker *can* pin a targeted tenant's single VM warm, so v1 **does not bill UDP warm-hours at all** and the design does not treat establishment-gating as an economic-DoS *prevention* — it is a mitigation (metering + kill-switch), and billing lands only once the kill-switch + unbilled-suspected-hours accounting is proven.
- **Bytes-relayed** rides the live-flow gauge mirroring `conn_count` (established flows only), same wiring as the DB splice — instrumented v1.

## 7. Testing / on-box e2e (REMAINING)

A `tools/dev test` gauntlet analog on a real microVM (this box is KVM/jailer-capable). Deploy a **generic UDP echo**, a **one-way UDP sink** (to exercise inbound-only liveness), and — as one example tenant — a real voice server as L4 tenants, drive a **stock UDP client**, and prove:

1. **Wake-on-first-packet cold-wake** — a first datagram from a cold project wakes it and round-trips; a stock client that speaks only its own wire works with **zero** jkbase bytes injected. Assert no app-protocol inspection anywhere on the path.
2. **Relay round-trip** — multi-packet exchange with datagram boundaries preserved (send N distinct-sized datagrams, assert N distinct replies, no coalescing) [P0-L4-7].
3. **Idle → hibernate in tens of seconds** — stop sending → after `UDP_RELAY_IDLE_TIMEOUT` + grace, `conn_count → 0` and prompt hibernate (assert FC pid gone / snapshot taken, and that it does **not** wait ~600s); **and** assert an HTTP-active project is NOT hibernated by an L4 last-flow eviction (no shared-clock back-dating — mechanics H5).
4. **One-way inbound-only liveness** — the sink promotes + stays warm on sustained inbound with **zero** replies (completeness H1); assert it does not hibernate-every-5s.
5. **Spoofed-source cost bound (Axis 1)** — flood magic-agnostic datagrams with rotating/spoofed sources → boot count bounded by the per-base-project cap + fair-share budget (`RateLimited`/`budget_full` drops); a single tenant's flood cannot deny another tenant's cold wake (assert cross-tenant fair-share) and does **not** stall a concurrent HTTP wake or squeeze it into RAM pressure (assert plane isolation) [P0-L4-2].
6. **Reflection bound (Axis 2)** — set `src = test-controlled victim`, drive ingress at rate `a`, assert *sustained* reflected egress ≤ `k·a` and the *one-shot* first datagram ≤ `C0`; assert the edge emits **zero** unsolicited packets pre-reply; assert a source-port-rotating spoofer does **not** multiply the per-source cap (IP-keyed); assert the kill-switch force-hibernates a high-ratio flow [P0-L4-6/-12].
7. **Transit-header auth + epoch** — inject a datagram to `agent_udp_port` with a bad/absent/replayed header, or a stale `(flow_id,epoch)`, → agent drops, nothing reaches loopback `:guest_port`; assert a `flow_id` reuse does not cross-wire two clients [P0-L4-11/-13].
8. **Readiness gate** — cold-boot a `0.0.0.0`-binding pure-UDP app → datagrams buffered until `/proc/net/udp` shows `00000000:guest_port` → replay → reply; and a never-binding app hits the readiness timeout → negative-cached, no boot loop (mechanics M2).
9. **Port stickiness + reuse quarantine** — redeploy keeps `external_port` with no ingress gap (runtime reconcile binds new before dropping old); a deleted project's port is **not** reallocated within quarantine (≥ SRV TTL), and a stale client's datagrams are not injected into a new tenant [M1].

## 9. Decisions — PROPOSED (awaiting sign-off)

- **(D1) UDP first; TCP L4 different-data-path follow-on.** v1 ships UDP. TCP reuses the control plane, rebuilds a *simpler* data path (§3(e)) because the kernel handshake gives return-routability for free.
- **(D2) Guest binds loopback + agent land-forward.** Rejected: eth0-bind + firewall — bypasses wake/quota/idle and exposes an unauthenticated UDP service to the hostile L2 segment [P0-L4-1].
- **(D3) Wake-on-first-packet, protocol-agnostic — bounded by rate/budget/egress caps, NOT by return-routability. This SUPERSEDES the earlier return-routability decision.** The trigger is source-spoofable and, for a stock UDP client, **unverifiable** — generic return-routability is provably impossible (§1.1). So we never authenticate the source. Axis 1 bounds cost (per-base-project wake-rate cap + UDP-plane-private per-tenant-fair-share concurrent-wake budget + global distinct-warm ceiling + host-RAM reservation + single-flight-gated permit + boot-timeout + spawned boot); Axis 2 bounds reflection (ratio amp-clamp `k`≈1 + one-shot `C0` + per-source(IP)/per-project/per-/24/**global** caps + generic keep-warm + kill-switch). **Reflection is BOUNDED (rate-limited), not eliminated.** Rejected: (a) claiming HTTP source-parity (a dishonest downgrade); (b) any edge-emitted challenge (breaks 100% of stock clients *and* is itself a reflector); (c) send-only heuristics (all passed trivially by a blind spoofer).
- **(D4) Load-bearing axes: cost-DoS (per-base-project wake-rate + per-tenant-fair-share global budget + global distinct-warm ceiling + RAM reservation) and reflection (per-source + per-project + per-/24 + global egress + ratio amp-clamp + generic keep-warm + kill-switch).** Per-source keying is worthless on the wake axis (spoofable) but decisive on the egress axis (the "source" is the reply destination — keyed on IP). Rejected: per-`(project,port)` wake keying (extra ports multiply budget); a *flat* global budget/flow-table with no per-tenant share (a single flood monopolizes it — the corrected cross-tenant fix, threat B1); an *absolute* `C0` (≈64–200× first-packet — the corrected ratio fix, threat H2).
- **(D5) Pinned external port via admin grant (e.g. `9987`); sticky random-alloc default + SRV fallback for others.**
- **(D6) New datagram pump; `relay_bidirectional` NOT reused** — byte-stream model destroys UDP boundaries and the reply-demux key [P0-L4-7].
- **(D7) New `UDP_RELAY_IDLE_TIMEOUT` (default 60s, floor 15s, ceiling 600s, per-port) on an un-throttled per-datagram clock; keep-warm on sustained traffic in EITHER direction (one-way apps supported); reuse `idle_detection_loop` but contribute an OWN last-activity signal ANDed with the other planes — never back-date the shared `ActivityTracker` (mechanics H5).** Rejected: the 30-day DB "never", the 600s stream default, reusing the throttled 30s stamp as the eviction clock, requiring bidirectional traffic to keep warm, and force-aging the shared clock.
- **(D8) NOT gapless across host-process restart** — flow table lost, clients reconnect; the edge socket is re-bound by a plain in-process bind (not socket-activation, which can't pre-declare a dynamic port; `SO_REUSEPORT` not used).

**v1 limitations (honest).** (i) UDP only — TCP L4 unbuilt. (ii) **Reflection is bounded, not zero** — a funded attacker spending continuous ingress can pull a sustained ~1× (≤3×) reflected stream at a victim, plus a rate-limited one-shot ≤`C0` spray per fresh victim and source-IP laundering; all inherent to protocol-agnosticism, contained by ratio caps + global egress budget + metering + the automatic kill-switch (§3(c) axis 2, §8). (iii) **Economic-DoS is bounded, not prevented** — a funded attacker can pin one *targeted* tenant's single VM warm (bounded by wake-rate + global warm ceiling); mitigated by UDP warm-hours being **unbilled in v1** + kill-switch, not by pretending establishment verifies the peer (P0-L4-12). (iv) **High-egress asymmetric apps unsupported by default** — an app whose *sustained* egress:ingress exceeds `k` (media broadcast / RTP push / game world-state fan-out / TFTP) is clamped; such a tenant needs an **admin-granted per-port egress ceiling decoupled from ingress** (analog of `l4 pin`), with the explicit note that raising it raises that port's reflection factor and moves protection entirely onto the absolute per-source/per-project/per-/24/global caps (completeness H2). (v) Not gapless across host restart (reconnect); stateful tuple-keyed sessions may reset across an aggressive hibernate cycle (§5, mechanics H4). (vi) No keepalive assumption ⇒ a tenant whose app's silence gaps exceed the port's `UDP_RELAY_IDLE_TIMEOUT` re-wakes on the next datagram (tunable per port). (vii) First-connect-after-deploy cold boot can exceed a short-connect-window app's first attempt (one-time blip). (viii) Warm-VM-hour billing instrumented but deferred (v1 = unbilled). (ix) Non-pinned tenants need an SRV record for discovery, which advertises the port publicly. (x) v4 only in v1; dual-stack requires /64-keyed aux maps as a **blocking** prerequisite (§5, threat M3).

**Build order:** decision-independent control work first — **DONE** (config, `PortAllocation`, `allocate_port`, deploy/teardown/reconcile, admin pin, CLI). Then the runtime socket-reconcile loop + datagram pump + flow-id/epoch transit + agent land-forward, then the generic wake-throttle (per-tenant fair-share budget + global warm ceiling + RAM reservation) + egress controls (ratio clamp + one-shot `C0` + per-source/per-project/per-/24/global + TTL-evicted maps) + `WakeError::RateLimited`, then firewall open + readiness/replay + observability + kill-switch + on-box e2e. This new untrusted external L4 seam **gets the multi-agent adversarial review before merge (project convention)**; the review must re-derive both bounds (P0-L4-2 cost, P0-L4-6 reflection) and probe: cross-tenant fair-share starvation of the global budget/flow-table, cross-plane RAM pressure vs the reservation, permit-per-boot single-flight (no multi-permit-per-burst), egress-clamp bypass / credit-accounting races / `C0`-spray, per-source IP-vs-ip:port keying + egress-map cardinality, transit-header forgery/replay + `flow_id`/epoch cross-wire, port-reuse cross-tenant injection, allocator/ephemeral collision, agent-map exhaustion, readiness boot-loop, and datagram-boundary/reply mis-demux. Deploy note: the agent-binary change ships an agent-rootfs update; no toolchain rebake unless a base layer changes (per [[prod-toolchain-rebake-on-build-change]]).

## 10. As-built — runtime seam + adversarial-review deltas

The runtime seam (§8 items 7–12) is **BUILT** across `jkbase-proxy` (`l4_plane` throttle/egress
controller + `l4_egress` pure credit/bucket types + `l4_ingress` datagram pump), `jkbase-agent`
(`l4_forward` land-forward), and `jkbase-server` (`l4_runtime` reconcile loop + `JKL4` iptables +
the wake/idle/metering wiring). The multi-agent adversarial review (6 dimension finders →
refute-by-default verification, 18 raw → 12 confirmed) ran and **all confirmed findings were
fixed**. Load-bearing as-built deltas vs. the design above:

- **Transit MAC is direction-bound (P0-L4-11, review HIGH).** The two legs share one per-VM secret
  but keep independent nonce windows, so a bare MAC over `flow_id‖epoch‖nonce‖payload` let an L2
  co-tenant replay a host→agent frame back at the host's return path (cross-direction replay). The
  MAC now prefixes an [`L4Dir`] domain-separation byte (`HostToAgent`/`AgentToHost`); the receiver
  passes the direction it expects, so a wrong-leg frame fails the tag. **Not on the wire** —
  `L4_HEADER_LEN` unchanged.
- **Hibernated L4 projects re-wake (review HIGH).** The pump does not latch a cached `vm_dst`: a
  reach-loop MISS re-validates VM liveness against the routing table (a hibernated project is
  removed from it), forwarding to a warm VM (no wake-rate spend) or entering the wake gate for a
  cold one. This also fixes the wake-rate being burned per-new-flow on an already-warm VM (new
  clients on a popular warm server are no longer throttled to the boot rate).
- **Keep-warm gates on ESTABLISHED flows only (P0-L4-12, review HIGH).** Provisional (spoofable)
  flows never stamp a keep-warm signal, so a spoof flood that never establishes cannot pin the VM
  warm past the base wake cost — hibernation gates purely on the L4 `conn_count` (established) gauge
  ANDed with the shared idle path, never back-dating the shared `ActivityTracker`.
- **The reflection kill-switch fires (P0-L4-6, review HIGH).** The metering loop force-hibernates
  the exact `reflection_suspected_projects()` set (the billing `warm_projects()` view deliberately
  excludes suspected bases), and the suspected flag auto-clears on a time window after a base
  quiesces.
- **Host-RAM floor accounts for in-flight boots**; `next_agent_udp_port` excludes every sibling
  stanza's `guest_port` (not just agent ports) so a multi-port project can't seat its transit
  listener on a port one of its own apps holds.
- **Agent flow-map self-bound (documented limitation).** With the synchronous host→agent teardown
  signal deferred (§7), the agent caps its `(flow_id,epoch)→loopback` map at 256 with a **120s**
  idle reaper and **LRU eviction on overflow** (not a fail-closed drop), so a churn flood cannot
  wedge the port; a recycled-then-returning flow transparently re-creates on its next datagram
  (best-effort loopback-port continuity, §9(v)). Genuine auth failures still drop fail-closed.
- **Known v1 limitation (review MEDIUM, accepted):** per-port tunables (`idle_timeout`/`amp_k`)
  changed on a **redeploy** do not propagate to an already-live edge socket, because the port is
  sticky and the reconcile loop does not rebind it. They take effect on the next fresh bind
  (new allocation / post-quarantine reuse). Acceptable — tunables are rarely retuned and never a
  safety boundary.
